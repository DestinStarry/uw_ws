# 运行与修改

已经直接部署在 `/home/zy/uw_ws`。新开WSL终端，不要source旧版工作空间。

```bash
source /opt/ros/humble/setup.bash
source ~/uw_ws/install/setup.bash
cd ~/uw_ws
ros2 launch uw_robot_bringup robot.launch.py
```

默认启动 `tcp_bridge_node`、`control_node`、`allocation_node`、`hardware_node`。
默认 `dry_run=true`，不打开物理串口；IMU默认关闭。TCP端口仍为8888。

启用IMU但保持串口输出关闭：

```bash
ros2 launch uw_robot_bringup robot.launch.py imu:=true dry_run:=true
```

香橙派系统Python已安装原有YbImuLib、确认串口和机械方向后，实际输出的启动方式：

```bash
ros2 launch uw_robot_bringup robot.launch.py imu:=true dry_run:=false
```

本次构建与离线测试不会替你执行实际输出命令。

每个观察终端也先source Humble和uw_ws，然后：

```bash
ros2 node list
ros2 topic echo /control/wrench       # 闭环想要的合力/力矩
ros2 topic echo /allocation/status  # 当前分配误差和规划状态
ros2 topic echo /actuators/command  # 最终四推力/两舵角
ros2 topic echo /hardware/tx        # 准备发送的STM32文本
```

每行echo会持续运行，分别在不同终端执行或Ctrl+C后切换。

参数文件 `src/uw_robot_bringup/config/robot.yaml` 分为5个节点区块：
控制增益看 `control_node`；舵速、推力变化率和规划周期看 `allocation_node`。
修改参数后重启。更换推进器安装几何时修改 `uw_robot_allocation/src/allocator.cpp` 的com/mounts，再重编译。

```bash
# 新终端只source Humble，再构建
source /opt/ros/humble/setup.bash
cd ~/uw_ws
export CMAKE_BUILD_PARALLEL_LEVEL=2
export MAKEFLAGS=-j2
colcon build --symlink-install --executor sequential --cmake-args -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON
source install/setup.bash
colcon test --packages-select uw_robot_control uw_robot_allocation uw_robot_hardware uw_robot_teleop
colcon test-result --verbose
python3 tools/parity.py
python3 tools/control_parity.py
bash tools/integration.sh
```

A：解锁/锁定；B：按住急停；Y：锁定时切换开环/闭环；X：有效深度下切换定深。
手柄JOY协议不变：`JOY:lx,ly,rx,ry,lt,rt,a,b,x,y,lb,rb\n`。

IMU是唯一Python业务节点。launch和验证工具使用Python，不参与闭环计算。
SDK需使用原实物可用的YbImuLib，确认 `/usr/bin/python3 -c 'from YbImuLib import YbImuSerial'` 可运行。

如果WSL遇到DDS发现不稳定，不能把进程存在等同于消息已连通；以验证记录为准。
