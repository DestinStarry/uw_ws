# 从哪里开始看代码

先看两个节点之间的边界：

```text
control_node：读手柄 + IMU + 深度 → 算六维目标 [Fx,Fy,Fz,Mx,My,Mz]
allocation_node：读六维目标 → 选舵角 → 分配四推力 → 正解回算误差
hardware_node：读四推力/两舵角 → 编号/归一化转换 → 串口发送
```

闭环节点不再创建规划线程、不求推进器推力，也不直接发布执行器命令。
解算节点不读取手柄、IMU或深度，不调姿态PID，也不负责串口。

| 文件 | 阅读目的 |
|---|---|
| uw_robot_control/src/control_node.cpp | 输入订阅、50Hz周期与六维目标发布 |
| uw_robot_control/src/controller.cpp | 姿态外环、角速度PI、定深和模式逻辑 |
| uw_robot_allocation/src/allocation_node.cpp | 接收目标、后台规划线程与执行器发布 |
| uw_robot_allocation/src/allocation_controller.cpp | 舵角估计、有效规划、门控及推力限速 |
| uw_robot_allocation/src/allocator.cpp | 唯一几何正解、解析反解、有界QP和数值舵角规划 |
| uw_robot_hardware/src/protocol.cpp | 深度文本解析、推力顺序转换和CTRL/OFF格式 |
| uw_robot_teleop/src/protocol.cpp | JOY格式和输入合法性 |
| uw_robot_interfaces/msg/ | ROS节点之间的数据约定 |

节点.cpp处理ROS通信；controller/allocator.cpp处理纯数学与状态；每个包test/验证自身职责。
`uw_robot_interfaces/include/.../robot_types.hpp` 仅共用小型数据结构和单位常量，不包含控制/分配实现。

## 九个业务话题

| 话题 | 消息 | 发布 → 订阅 |
|---|---|---|
| /control/request | ControlRequest | tcp_bridge → control |
| /imu/data | sensor_msgs/Imu | imu → control、tcp_bridge |
| /depth/state | DepthState | hardware → control、tcp_bridge |
| /control/wrench | WrenchCommand | control → allocation |
| /robot/status | RobotStatus | control → tcp_bridge |
| /allocation/status | AllocationStatus | allocation → 调试观察 |
| /actuators/command | ThrusterCommand | allocation → hardware |
| /hardware/tx | std_msgs/String | hardware → 调试观察 |
| /hardware/rx | std_msgs/String | hardware → 调试观察 |

control/wrench包含使能、闭环/开环、回中请求，以及机体系N/N·m目标，不包含推进器推力。
actuators/command内部推力顺序仍是 `[1上,3下,2右,4左]`，舵角rad。
hardware统一变为STM32物理顺序 `[1上,2右,3下,4左]`；正向除33N、反向除24.5N，舵角除π/2。
不会在两个节点各自重复做这次顺序转换。

## 三段超时保护

1. control：JOY超过0.35s，或闭环IMU超过0.1s，锁定并输出禁用目标。
2. allocation：control/wrench超过0.15s，发布禁用执行器；规划超过有效期则零推力。
3. hardware：actuators/command超过0.15s，发送OFF。

停止、重解锁、切模式改变epoch；控制进程重启改变session。解算节点据此清空状态并作废旧后台规划，避免将停机前结果用于新一轮输出。
ROS时间检查传输年龄，steady_clock检查本地等待时间。实际调度/串口延时会叠加，不是硬实时保证。
STM32仍应有独立串口超时回中，ROS进程全部停止时无法持续发送OFF。
