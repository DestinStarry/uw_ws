# 下水测试日志与事后分析

日志参考原 `orange.10.20/flight_logger.py` 的 CSV 与后台落盘方式，改为独立 ROS 节点 `uw_robot_logging / flight_logger_node`。控制、分配、硬件节点不调用它写盘；日志节点没有执行器或控制命令发布者。

## 1. 正常使用：整机启动自动记录

先更新源码并编译，再加载环境：

```bash
cd ~/uw_ws
bash scripts/check.sh
source install/setup.bash
```

整机入口默认 `logging:=true`。使用原有启动命令即可，可为本次测试加标签：

```bash
ros2 launch uw_robot_bringup robot.launch.py \
  dry_run:=false imu:=true depth_source:=i2c camera:=true \
  log_label:=pool_01
```

这条命令启用真实执行器通信。首次验收仍按原流程断开推进器动力检查；日志功能不代替急停。无设备软件调试可用 `dry_run:=true imu:=false depth_source:=none camera:=false`，也会生成日志，并在元数据中记录 dry-run 状态。

日志可选：在整机命令后加 `logging:=false`，完全不启动日志节点；加 `logging:=true` 则启动后立即记录，省略时实物默认开启。完整的开/关两套命令见 README 的启动部分。

使用 `logging:=false` 启动整机后，如需临时补开日志，另开终端执行：

```bash
source ~/uw_ws/install/setup.bash
ros2 launch uw_robot_bringup logger.launch.py log_label:=pool_01
```

这只启动记录节点，不重复启动控制、串口或传感器。完全关闭时没有日志 start/stop 服务；已有记录节点时直接使用这些服务，不要启动第二个记录节点。

每次启动建立新的会话目录，默认在 **`~/uw_logs/`**，例如：

```text
~/uw_logs/20261125T030000_123456Z_a1b2c3d4_pool_01/
├── flight.csv       默认 50Hz 的最新消息快照，203列
├── events.jsonl     原始收发、输入命令、状态变化、参数变化等事件
├── metadata.json    记录频率、话题、标签、主机、Git版本及配置来源
├── robot.yaml       启动时所指定参数文件的副本（文件存在时）
├── parameters.json  实际运行节点参数，异步成功取得后生成
└── summary.json     结束原因、行数、队列丢记录计数与写盘状态
```

目录名和 wall_time_utc 使用 UTC（Z），带随机标识，避免同一秒运行或时钟回拨覆盖旧数据；原始中文标签会保留在 metadata 中。CSV 另有单调时钟 elapsed_s，不用系统日期跳变推断采样间隔。

不必一直解锁才记录：上电、标定、未解锁、急停、断链与恢复阶段都有分析价值。当前版本默认不录视频、原始图像或 ROS bag。

## 2. 下水前确认正在记录

另开已加载环境的终端：

```bash
source ~/uw_ws/install/setup.bash
ros2 topic echo /logging/status --full-length
```

正常看到 `state: recording`、`recording: true`，`csv_rows` 持续增加，且 error 为空。String 内容为 JSON；`session_dir` 给出本次目录的完整路径。应同时留意 dropped_csv、dropped_events 和剩余空间。

若提示 disk_low、session_size_limit、failed 或 error，不应以为日志仍正常录制。控制链不会因日志故障自动关闭，需要操作者决定是否继续本次试验。

## 3. 一次启动内手动分段

结束当前记录（不会停止机器人控制）：

```bash
ros2 service call /logging/stop std_srvs/srv/Trigger '{}'
```

需要下一份时，可先设置标签，再开始：

```bash
ros2 param set /flight_logger_node session_label pool_02
ros2 service call /logging/start std_srvs/srv/Trigger '{}'
```

再次 start 会创建新目录，不覆盖旧文件。记录中重复 start 会被拒绝，避免意外切段。设置标签仅影响下一次新会话。

整组 `Ctrl+C` 时会停止接收新记录，并尝试排空队列、flush/fsync 后生成 summary.json。若 stop 返回 draining/失败，不要立即断电：继续查看 status，等待 closed 与 summary.json；存储长时间卡死时，关闭等待有上限，不能保证所有尾部数据保存。

突然断电或 kill -9 无法执行收尾，可能没有 summary.json 或丢失最后一部分数据。默认每约 1秒 flush/fsync 是尽力减少损失，不是断电零丢失保证。

## 4. 单独记录、关闭与仿真

已有控制链在运行但未启动记录节点时，可只启动记录器：

```bash
ros2 launch uw_robot_bringup logger.launch.py log_label:=manual_01
```

它只订阅话题，不会启动传感器或执行器。不要与整组自动日志同时运行第二个记录器，避免服务名称冲突。

关闭整组默认记录：

```bash
ros2 launch uw_robot_bringup robot.launch.py \
  dry_run:=true imu:=false depth_source:=none camera:=false logging:=false
```

仿真默认不记录，可显式开启，并在 metadata 中标为 simulation：

```bash
ros2 launch uw_robot_bringup simulation.launch.py \
  headless:=true camera:=false logging:=true log_label:=sim_01
```

## 5. 记录了哪些数据

| 内容 | CSV 中的主要字段 | 解释 |
|---|---|---|
| 电脑控制输入 | cmd_u/v/w/p/q/r、cmd_arm/estop/depth_toggle/loop_toggle | ROS 转换后的物理量与按钮输入，不是手柄原始轴值 |
| 控制状态 | armed、closed_loop、depth_hold、robot_state、cycle_dt_s | 控制器实际报告的状态及周期 |
| IMU | imu_qw/qx/qy/qz、roll/pitch/yaw、gyro、accel | ROS 单位；角速度 rad/s、加速度 m/s²，欧拉角度数 |
| 深度 | depth_m、depth_rate_mps、depth_valid、depth_data_age_s、depth_error_m | 深度向下为正；误差仅在有效定深状态计算 |
| 目标力矩 | target_fx/fy/fz/mx/my/mz、session、epoch | 控制器发送给分配器的目标 |
| 分配诊断 | achievable_*、achieved_model_*、planner_ms、gate_* | 模型计算值和门控，不是实测推力 |
| 执行器 | force_up_1/down_3/right_2/left_4_n、servo_command_*、gripper_closed | 内部顺序 [1上、3下、2右、4左]；是命令不是测量 |
| 舵角规划 | servo_target_*、servo_estimated_* | 规划和估计角度，不是舵机编码器测量 |
| 串口指令 | hardware_tx、serial_command、ctrl_f1~f4/s1/s2/gripper | 保留最终 CTRL/OFF 文本，OFF 不伪造成七个数值命令 |
| MCU 遥测 | mcu_voltage_v、rpm_0~3、mcu_ch_ready、mcu_spi_errors、mcu_stop_reason 等 | 从常规与 DIAG 原始字段提取，原文仍在事件文件 |
| 温度 | cpu_temperature_c | Orin CPU 温度，不是水温或 MCU 板温 |
| 日志健康 | log_queue_depth、log_dropped_csv、log_dropped_events | 后台积压与本地队列丢记录情况 |

`rpm_0～rpm_3` 对应物理电机 1～4；推力数组的内部顺序是 [1、3、2、4]，对应列名已带物理编号。分析转速与推力时按编号对齐，不按 CSV 列位置直接配对。转速大小也不能直接当作已测推力。

每类 ROS 消息都有 receive_age_s、stamp_s、source_age_s、fresh 列；MCU 各字段也有独立的接收年龄。新的 DIAG 不会把旧 RPM 当作新值刷新。fresh 使用记录器的观察阈值（写入 metadata 的 receive_timeout_s），不替代源端 valid 或控制策略；当前深度阈值 0.5秒，分析时仍应结合参数快照。

CSV 默认是 **50Hz 最近消息快照，不是多传感器硬件同步采样，也不是所有 ROS 消息的逐条录制**。100Hz IMU 在 CSV 中会下采样；可设置 record_imu_events=true，额外把收到的每条 IMU 放进 events.jsonl。命令、原始 hardware/tx/rx、状态变化默认保留事件。

缺失、非有限数或串口 -- 对应空白字段，不补成 0；对于历史缓存、显式 valid=false 的数值，分析时还必须看有效性和年龄。0 RPM 与未收到反馈不同。

原参考 logger 中的 PID 内部分量、完整求解器内部状态等未全部通过当前 ROS 消息发布，因此不能虚构对应数值。需要这些数据时，应扩展诊断接口再记录。

## 6. 参数与空间管理

robot.yaml 的 flight_logger_node 节配置：

| 参数 | 默认 | 作用 |
|---|---|---|
| sample_hz | 50.0 | CSV 快照频率，允许 1～200；资源紧张可降为 20 |
| flush_interval_s | 1.0 | 工作线程刷新间隔 |
| queue_size | 4096 | 内存队列上限，满时丢新记录并计数，不无限增长 |
| fsync | true | 刷新时请求同步到存储 |
| min_free_mb | 512.0 | 低于此剩余空间停止记录并报告 disk_low |
| max_session_mb | 2048.0 | 单会话 CSV+事件体积上限；0 表示不限 |
| auto_start | true | 节点启动自动开始；false 可等待 start 服务 |
| record_imu_events | false | 是否额外逐条记录 IMU 事件 |
| parameter_capture_timeout_s | 12.0 | 启动后尝试发现运行参数服务的时段 |

整组的 log_dir、log_label 参数分别覆盖输出根目录和会话标签。参数服务未发现的节点不会被伪造出参数；parameters.json 只含成功取得的内容。记录中所观察到的参数变化另有 parameter_change 事件，便于追溯调参。

采样频率 sample_hz 是节点启动设置，修改后应重启日志节点；队列、刷新和空间限制等会话设置在下次 start 读取，不热改当前写入器。参数事件说明 ROS 参数发生了变化，不保证其它控制节点实现了对应参数的热更新。

config 副本是指定 YAML 的原始内容，可能与 launch 覆盖值不同；复现实验应结合 parameters.json、参数事件和 metadata。Git 信息只记录本地 HEAD 与是否有未提交修改；部署目录没有 .git 时记录未知。

磁盘写入在独立节点的后台线程执行，不改控制算法；它仍占用系统 CPU、内存和存储，不能据此承诺完全没有资源影响。首次长时间测试应观察空间、队列与控制周期，按需降低采样率。该功能不自动删除旧日志。

## 7. 下水后取回与分析

正常停止后，将 **整个会话目录** 用 SFTP/WinSCP 拷回电脑，不只拷 CSV。CSV 可用 Excel（UTF-8）或脚本分析；事件和配置对解释急停、传感器失效、SPI 错误及调参很重要。

快速生成摘要，替换下面的会话目录：

```bash
ros2 run uw_robot_logging log_summary ~/uw_logs/实际会话目录名
```

在没有 ROS 的电脑上，也可从仓库根目录直接执行 `python src/uw_robot_logging/uw_robot_logging/summarize.py 会话目录`。

摘要按流式方式读取 CSV，不要求 pandas，也不一次加载大文件。范围统计包含缓存值，只能作为粗看；做具体结论时应过滤 fresh/valid/usable 和源数据年龄。没有最终 summary 的会话会标为未完成或仍在录制。

summary.json 中 clean_close 只表示日志线程正常收尾，**不代表控制测试成功、没有 ROS/DDS 丢包或 MCU 确认执行了停机**。队列丢记录计数也只描述本日志进程能观测到的损失。

## 8. 离线验证入口

```bash
colcon test --packages-select uw_robot_logging
colcon test-result --verbose
python3 tools/flight_logger_smoke.py
python3 tools/flight_logger_launch_smoke.py
```

测试使用临时目录、假消息与 dry-run，不连接真实推进器。字段/服务验证使用同一隔离 executor 内的假消息节点和真实记录节点；整组检查使用独立日志进程与真实 dry-run 控制/硬件节点。包括 CSV/事件/参数及参数变化、无效值、空间限制、队列溢出、写盘失败、分段与退出收尾，以及日志失败或退出不关闭控制组。
