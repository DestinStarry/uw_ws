# 工程规范

本文件约定 `uw_ws` 的目录分层、命名、注释与测试要求。新增代码与重构都按此执行，
评审时也以它为准。

## 一、分层

工作区按"数据流方向"分包，**依赖只能向下**，不允许反向引用：

```
uw_robot_interfaces   纯类型与消息（无节点、无 IO）
        ↑
uw_robot_control      算法：闭环 + 分配（不碰 socket/串口）
uw_robot_communication 传输：TCP 与 STM32 串口（不写控制算法）
uw_robot_sensors     传感器：IMU / MS5837 / 相机（不写控制算法）
uw_robot_mujoco      仿真替身：只实现被替换掉的那部分硬件
uw_robot_bringup     装配：launch + 参数（不含逻辑）
```

每个 Python 子包内部再分三层，`depth` 是范例：

| 层 | 职责 | 约束 |
|---|---|---|
| 设备层（`ms5837.py`） | 寄存器访问、数据手册解算 | 无 ROS、无线程，纯函数可离线单测 |
| 服务层（`driver.py`） | 线程、标定状态机、失效判定 | 无 ROS，可注入假设备 |
| ROS 层（`depth_node.py`） | 参数、发布策略、日志 | 只做"翻译"，不放算法 |

C++ 对应关系：`controller.cpp`/`allocator.cpp` 是算法，`*_node.cpp` 只做 IO 与接线。

## 二、命名

| 对象 | 规则 | 例 |
|---|---|---|
| 文件 | 小写 + 下划线 | `allocation_controller.cpp` |
| 类型 | 大驼峰 | `WrenchTarget` |
| 函数/变量 | 小驼峰 | `attitude_moment`、`rate_error` |
| 常量 | `k` 前缀或全大写（头文件常量用 `constexpr`） | `kPlanTargetTolerance` |
| 消息字段 | 小写下划线 + 单位后缀 | `depth_m`、`servo_target_rad` |
| 参数 | 小写下划线 + 单位后缀 | `rate_integral_limit`、`servo_rate_rad_s` |

**单位必须进名字或注释**：`_m`、`_mps`、`_rad`、`_rad_s`、`_n`、`_nm`、`_s`、`_hz`。
坐标统一 ROS REP-103：+X 前进、+Y 左舷、+Z 向上。

## 三、注释

1. **每个文件一个文件头**（C++ `/// @file`，Python 模块 docstring）：说明职责、
   单位、线程模型、与相邻模块的边界。
2. **每段逻辑一个"为什么"**，不要复述代码。例：
   ```cpp
   // 松杆后用上一拍力矩反算积分初值，保证切换瞬间力矩连续。
   ```
3. **参数默认值旁写量纲与来源**：`V3 rate_kp{1, 1.5, 1.5};  // N·m/(rad/s)`。
4. 已废弃的写法用 `// 注意：` 标出原因，不保留死代码。

## 四、错误处理

| 场景 | 做法 |
|---|---|
| 参数非法 | 启动阶段抛异常/`ConfigError`，**不要**带病运行 |
| 设备读失败 | 计数 + 置失效 + 低频重连；**不要**返回上一次的旧值 |
| 输入帧非法 | 整帧丢弃，不做部分采纳 |
| 超时 | 一律停机并进入安全状态，要求重新解锁 |

## 五、测试

| 层 | 要求 |
|---|---|
| 纯算法（控制器/分配器/解算） | 必须有单元测试，直接构造输入，不启动 ROS |
| 传输协议 | 解析/格式化的往返测试（非法输入必须被拒） |
| 节点 | 至少能被 launch 起来的冒烟测试 |

约定：`python3 -m pytest <包>/test -q` 与 `colcon test` 必须全绿；
`uw-hello` 这类脚手架包不进入验收。

## 六、构建与检查

```bash
tools/check.sh          # 编译 + 单测 + 一致性对比（提交前必跑）
bash tools/build.sh     # 只编译
```

- 构建产物（`build/`、`install/`、`log/`、`__pycache__/`、`*.pyc`）不进仓库；
- `validation/` 只保留结论报告，不保留日志；
- 提交信息写"改了什么 + 为什么 + 怎么验证"，一次提交一件事。

## 七、配置

- 参数全部集中在 `uw_robot_bringup/config/robot.yaml`（控制/分配/通信/传感器）与
  `plant.yaml`（仿真对象），代码里只允许出现"默认值"，且必须与 yaml 一致；
- 新增参数必须同时更新：yaml、`load_config()` 校验、包 README 的参数表；
- 单位与坐标系必须在 yaml 注释里写明。
