# 控制只响应一次：接收与恢复修复

## 日志结论与修复边界

flight.csv 中 Orin 在约10.48秒解锁，13.06秒首次记录到 MCU ACTIVE=0 / NEUTRAL_REQUIRED=1 / STOP_REASON=8，此后 Orin 仍保持姿态闭环并发送非零 CTRL，直到24.58秒锁定。首次接收故障的具体诱因尚未由日志确定。

此次同时更新 Orin 和 STM32：修复两端恢复状态不一致，减少接收中断工作，并增加可追溯诊断。没有取消200ms控制看门狗、100ms帧年龄、故障回中或显式重新解锁要求；没有修改PID、PWM映射、引脚或电调RPM算法。

## 必须配套更新

1. 停止所有旧ROS控制组、串口调试工具和电脑UI，断开推进器动力。
2. 烧录新的 low_control3（构建本身不会自动烧录）。不要使用旧的Debug构建产物，先重新构建所选配置。
3. 上传并编译新版 uw_ws / uw_ws_orin，加载新的 install/setup.bash。
4. 首次启动保持锁定，确认 hardware/control_status 从 WAIT_MCU 变为 DISABLED，然后测试零推力握手与故障停机。

新版Orin实物入口要求新版MCU的SAFETY心跳及SYNC确认；旧MCU不会通过握手，禁止为了兼容而关闭保护。新版MCU保留CTRL/OFF格式，但旧Orin缺少SYNC握手，不能解锁新版MCU。

## STM32修改

- UART接收中断只向1024槽位字节环形缓存保存字节和接收时刻；分帧和解析移到主循环。环形缓存溢出立即走IRQ停机路径；帧年龄仍从首字节时刻计算。
- 上电/故障后强制要求新编号SYNC；普通零推力CTRL和旧SYNC不能恢复。新增 SYNC:<非零uint32编号>。处理时将四推进器、两舵角和夹爪命令均置中立，确认编号写入SAFETY；不携带旧推力或旧舵角。重复SYNC保持中立并续期。OFF/故障清除确认编号。
- 每100ms发送SAFETY；原DIAG仍1Hz，常规电压/RPM仍10Hz。
- RXSTAT按1Hz提供UART错误次数/标志、重挂失败、字节/行队列溢出、非法字节、超长、半帧超时、过期、非法命令及等待零推力拒收计数。
- CH9434故障后的50ms阻塞初始化只允许在控制未激活时重试。反馈缺失不作为推力门控，但不允许运行中的失败重试周期性阻塞控制任务。

```text
SAFETY SEQ:12 MS:12340 ACTIVE:1 NEUTRAL:0 SYNC:123456 FAULTS:3 REASON:8
RXSTAT UART:2 FLAGS:8 REARM:0 BYTE_OVF:0 LINE_OVF:0 BAD_BYTE:0 TOO_LONG:0 PARTIAL_TIMEOUT:0 STALE:0 INVALID:0 NEUTRAL_REJECT:4
```

FLAGS是STM32 HAL UART错误位累计OR：1=PE、2=NE、4=FE、8=ORE；例如8指曾出现溢出。它不是本次错误的唯一归因，也不能单靠累计值推断新错误；对比计数增量。FAULTS是停机故障代数，用于识别期间发生过故障，不等于独立物理故障次数；同一IRQ故障可能由ISR和主循环处理各递增一次。REASON仍是最近一次停止原因，恢复后可以保留历史非零值。

## Orin修改

- hardware_node真实串口模式下先发OFF等待新格式心跳；新解锁只发送带新编号的SYNC，收到匹配编号且ACTIVE=1、NEUTRAL=0后才允许发送分配器的CTRL。
- 心跳超过0.35秒不更新、握手超过0.6秒、MCU停机/故障代数变化/重启、执行器命令超时均阻断输出。握手不成功不会发送非零CTRL。
- hardware/control_fault以50Hz发布Bool；hardware/control_status提供WAIT_MCU、DISABLED、SYNCING、ACTIVE或FAULT:原因。
- 实物robot.launch.py在dry_run=false时强制control_node.hardware_feedback_required=true。控制器收到故障或该反馈超过0.3秒未更新即退出解锁，robot/status显示HARDWARE_FAULT，电脑沿用已有ARMED回传显示未解锁。
- 故障解除不自动继续旧推力。需要收到禁用执行器状态、释放解锁按钮并重新明确解锁；新解锁使用新编号，再次完成零推力握手。持续按住按钮不会自动恢复。
- 串口原始接收发布队列和TCP桥订阅队列均为100，适配VOLT/SAFETY/DIAG/RXSTAT连续多行，避免电压/RPM行被单条缓存覆盖。
- dry_run保持无真实串口，仿真入口不要求MCU心跳。单独启动control_node时默认不要求此反馈；真实执行请使用整机入口，避免漏掉联锁装配。

## 无动力验收

```bash
source ~/uw_ws/install/setup.bash
ros2 topic echo /hardware/control_status
ros2 topic echo /robot/status
ros2 topic echo /hardware/tx --full-length
ros2 topic echo /hardware/rx --full-length
```

按正常整机命令启动。初始DISABLED且发送OFF；释放按钮后按解锁，应短暂SYNCING，随后ACTIVE并发送CTRL。出现FAULT/HARDWARE_FAULT时应立即锁定，停止非零发送。修复接收/心跳后仅恢复连接不应重新出力；重新按解锁应产生新SYNC编号。

先在推进器无动力状态验证，再按实际推进器使用要求开展水中低输出实测。串口或系统异常时不要绕过联锁，也不要在真实串口上运行伪设备测试脚本。
