# 摄像头第七路舵机与Xbox十字键

第七路已从夹爪改为摄像头，0°表示镜头朝前、中位PWM1500μs，范围−90°～+90°。Xbox左下十字键：上按一次目标+10°，下按一次−10°；松开保持，长按不重复，左右方向不改变角度。程序启动目标0°。UI显示的是目标，不是舵机实测反馈。

## 链路与独立控制

电脑发绝对角度，避免重复网络帧导致重复步进：

```text
CMD:u,v,w,p,q,r,arm,estop,depth,loop,camera_deg
```

前10字段保持原语义；兼容旧10字段输入（没有摄像头更新）。新第11字段为有限角度，范围±90°，非法值拒绝整帧。TCP桥发布`/camera/servo_target_deg`（std_msgs/Float64），hardware_node独立订阅，初值0°并保持最后有效目标，无需推进器解锁或IMU就绪。

下行正常启用控制时仍为7个数，第七个数改为摄像头角度/90：

```text
CTRL:f1,f2,f3,f4,s1,s2,camera_normalized
```

锁定、急停、分配失效或命令超时时：

```text
OFF:camera_normalized
```

例如+10°为`0.1111`，−10°为`−0.1111`。OFF扩展先停止四个推进器、前两路转向舵机回中，再只更新摄像头。普通`OFF`保持现有摄像头位置。STM32自身CTRL看门狗超时和low3 SysTick停机同样保持摄像头。断电/复位后重新居中。

MCU第七路为第三舵机TIM8_CH3/PI7，计算`PWM=1500+round(normalized*500)`，限制1000～2000μs（±90°）。+10°约1556μs，−10°约1444μs。原始数字`7 PWM`也限制到这个范围；1～6路数字命令原行为不改。SPI、转速采集及电机/前两舵机驱动不改。

默认正目标对应增加PWM，实际顺/逆时针取决于安装。若上键实际逆转，将robot.yaml的hardware_node参数`camera_direction`从1改为−1，重新启动hardware_node即可；其余控制轴不受影响。

锁定时摄像头仍可调整；急停停止推进器，摄像头保持最后目标，电脑仍在线时十字键可继续调整。关闭UI不会使摄像头回中，但STM32重新上电回0°。重开UI会从0°重新发送目标，因此会回中。

## 更新顺序

这次需同时更新电脑UI、Orin源码和STM32固件。先停止整机控制，烧录本次low2或low3固件，再更新Orin与UI。不要把新Orin与旧STM32混用：旧low3不认识OFF角度扩展，旧固件第七数也仍是夹爪语义。

Windows电脑运行更新后的`main.py`，同目录必须有新增的`camera_pan.py`及更新的`command_mapper.py`。Orin更新整个源码目录后：

```bash
cd ~/uw_ws
bash scripts/check.sh
source install/setup.bash
```

整机启动命令和日志开关不变。无需改JetPack、内核或安装新ROS消息包。

## 单独验证（先不驱动推进器）

在正常运行hardware_node后观察：

```bash
ros2 topic echo /camera/servo_target_deg
ros2 topic echo /hardware/tx --full-length
```

不开手柄时可单次发目标验证Orin到STM32：

```bash
ros2 topic pub --once /camera/servo_target_deg std_msgs/msg/Float64 '{data: 10.0}'
```

先保持推进器锁定，按上/下各一次应分别变化10°，长按不连转，最大±90°。然后解锁/锁定，摄像头应保持原角度。最后验证原前六路、急停、串口失联停机和转速反馈。

新接口无需改现有ControlCommand等ROS消息定义。日志保留`/hardware/tx`原始帧，记录中第七数可还原摄像头目标；旧日志把它称为夹爪的列名属于历史命名，不表示当前仍有夹爪。

## 软件验证边界

UI边沿/限位、TCP解析/串口编码、low2和low3的摄像头保持/限幅/停机，以及TCP→ROS→PTY整链路均有测试。没有自动烧录或连接实物，实际顺转方向、限位和舵机角度仍需按安装验收。
