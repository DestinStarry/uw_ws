# 直接运行

## 构建

在新WSL终端仅加载ROS2，再构建，避免已加载的旧工作空间覆盖环境：

```bash
source /opt/ros/humble/setup.bash
cd ~/uw_ws
colcon build --symlink-install --executor sequential --cmake-args -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON
source install/setup.bash
```

## 统一启动

```bash
# 默认dry-run，不打开真实串口；IMU、相机默认关闭
ros2 launch uw_robot_bringup robot.launch.py

# 控制链与相机启动，仍不打开真实串口
ros2 launch uw_robot_bringup robot.launch.py camera:=true

# 实物：需要对应ROS环境、串口权限、IMU SDK和实际相机
ros2 launch uw_robot_bringup robot.launch.py imu:=true camera:=true dry_run:=false
```

默认启动4个节点，IMU和相机分别由参数开启。Ctrl+C统一退出。
核心控制/分配/通信进程退出会结束整组启动；相机失败不结束控制链，避免预览故障直接干扰控制生命周期。
香橙派旧Ubuntu20.04上的Python脚本可运行，不代表已具备本ROS2 Humble工程的运行环境。

## 单独启动节点

```bash
ros2 run uw_robot_control control_node
ros2 run uw_robot_control allocation_node
ros2 run uw_robot_communication tcp_bridge_node
ros2 run uw_robot_communication hardware_node
ros2 run uw_robot_sensors imu_node
ros2 run uw_robot_sensors camera_node
```

单独启动用默认参数；通常建议使用统一launch加载robot.yaml。不要与统一launch重复启动同名节点或重复占用设备。

只验证相机：

```bash
ros2 launch uw_robot_bringup camera.launch.py
# 没有USB相机，仅验证接口
ros2 launch uw_robot_bringup camera.launch.py synthetic:=true http_port:=18080
```

HTTP地址保持`http://主机IP:8080/?action=stream`。真实相机由OpenCV独占采集，不同时启动mjpg_streamer或旧main.py。

## 检查

```bash
colcon list
ros2 pkg executables uw_robot_control
ros2 pkg executables uw_robot_sensors
ros2 pkg executables uw_robot_communication
ros2 topic echo /control/wrench
ros2 topic echo /allocation/status
ros2 topic echo /hardware/tx
```

## 测试

```bash
bash tools/check.sh
python3 tools/launch_smoke.py
python3 tools/camera_launch_smoke.py
bash tools/integration.sh
```

前三类检查为单元/数值对照/启动生命周期/合成相机；integration使用伪串口和假IMU，绝不打开物理推进器。
WSL跨进程DDS有已知发现/图像传输不稳定，不能把进程存在或单元测试通过等同于真实水下控制通过。
