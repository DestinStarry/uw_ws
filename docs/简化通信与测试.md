# 简化通信与测试

当前版本采用直接 `CTRL/OFF`，取消此前的SYNC握手、MCU心跳门槛、hardware/control_fault联锁和等待零推力恢复状态。控制由Orin解锁状态统一决定，STM32只执行完整合法指令。旧握手文档属于历史方案。

## 正常数据流

电脑手柄 → Orin控制/分配 → 50Hz CTRL → STM32 PWM。

```text
CTRL:f1,f2,f3,f4,s1,s2,gripper
OFF
```

每条以换行结束。CTRL为7个[-1,1]的有限十进制数；f1～f4按物理电机1～4顺序，s1/s2是归一化舵角，夹爪仍为±0.5。保留既有电机方向、推力换算和舵机PWM映射。

STM32上电输出中位，收到合法CTRL直接执行，不要求先发零推力或握手。OFF立即回中；UART错误、非法/过期帧或队列溢出丢弃并恢复分帧，不刷新最后有效控制时间。最后有效输出最多保持至200ms看门狗截止；后续新完整合法CTRL可以继续执行，无需重新进行MCU解锁。200ms内没有有效CTRL会停机，独立SysTick和IWDG保留，BUZZ/坏帧不续期。中断仅缓存字节，保留已修复的HAL错误回调顺序。

这意味着：如果Orin仍保持解锁，短暂串口故障或断链恢复后，STM32会按后续最新合法CTRL恢复输出。锁定或急停请在电脑端操作，由Orin持续发送OFF；恢复动作前先回中摇杆。简化逻辑不证明线路故障已经消除。

Orin仍保留电脑指令超时、IMU失效、急停及执行器命令超时保护；不再根据STM32的诊断/转速/心跳主动解除解锁。无法从Orin的armed状态单独断言MCU实际已执行。

## 上报只保留一行

默认10Hz：

```text
VOLT:23.80 CH0:0 CH1:1200 CH2:-- CH3:--
```

不发送SAFETY/RXSTAT，不默认发送DIAG。需要开发诊断时可在BoardConfig.h将kDiagnosticsEnabled改为true后重新编译，1Hz附加原DIAG；诊断不参与控制。日志仍可选、默认50Hz，摄像头/IMU/深度/Orin温度不受影响。

转速有效0与无反馈不同。low_control2的_rpm数组初始为0，未收到正确CRC帧时也可能一直输出0，因此UI显示0不等于反馈正常。当前保留有效性：实际解出零转速显示0，未收到/错误/过期显示--，不会将缺失数据补零。转速无论是否有效，都不阻止推进器控制。

## 更新和启动

停止旧ROS组与串口调试器，备份现有实机配置。Orin需上传当前精简源码并编译；新Orin下行与low_control2的CTRL/OFF兼容，可以先保留low_control2作基线测试。若使用low_control3，则烧录当前精简版，不能继续使用强制SYNC的中间版本。

```bash
cd ~/uw_ws
source /opt/ros/humble/setup.bash
bash scripts/check.sh
source install/setup.bash
ros2 launch uw_robot_bringup robot.launch.py \
  dry_run:=false imu:=true depth_source:=i2c camera:=true \
  monitor:=true tcp:=true logging:=true log_label:=simple_test_01
```

不记录时改成logging:=false。保持锁定先检查传感器，再在推进器动力断开时验证前推、后推、急停和电脑断链。正常按Ctrl+C结束会保存日志；日志本地目录~/uw_logs，每次独立会话。不再有WAIT_MCU/SYNCING和hardware/control_status话题。

```bash
source ~/uw_ws/install/setup.bash
ros2 topic echo /robot/status
ros2 topic echo /hardware/tx --full-length
ros2 topic echo /hardware/rx --full-length
```

这些查看命令按需在不同终端执行。解锁后tx应为CTRL；锁定、急停或上游超时后应为OFF。RX默认只见VOLT/CH行。要确认实际推进器停机仍需实物测量，先完成无动力验证。

## 离线验证

```bash
python3 tools/simple_control_smoke.py
```

使用伪串口与真实控制/分配/通信进程，验证没有MCU心跳和有效RPM时可直接连续控制，以及前后方向、急停、重新解锁和电脑指令超时停机。固件6组本机测试另验证直接CTRL、错帧不续期与下一有效帧恢复、200ms停机、输出范围和UART回调顺序。测试不打开真实设备。
