# 结构和接口

## 目录

```text
src/
├── uw_robot_control/                 C++
│   ├── include/uw_robot_control/
│   │   ├── closed_loop/controller.hpp
│   │   └── allocation/{allocator,allocation_controller}.hpp
│   ├── src/closed_loop/              姿态/角速度、定深、目标力矩和状态管理
│   ├── src/allocation/               几何正解、反解、规划与推力分配
│   └── test/{closed_loop,allocation}/
├── uw_robot_sensors/                 Python
│   ├── uw_robot_sensors/imu/         YbImu驱动与ROS节点
│   ├── uw_robot_sensors/camera/      capture、stream、camera_node
│   └── test/
├── uw_robot_communication/           C++
│   ├── include/uw_robot_communication/{tcp,stm32}/
│   ├── src/tcp/                     CMD收帧、TCP连接、基础状态回传
│   ├── src/stm32/                   UART读写、CTRL/OFF编码、深度解析
│   └── test/{tcp,stm32}/
├── uw_robot_interfaces/              ROS消息、robot_types.hpp
└── uw_robot_bringup/                 launch、config/robot.yaml
```

每个C++节点只连接其所属的内部逻辑库。闭环与分配虽然在一个包，仍使用两个进程，避免非线性求解阻塞闭环。
IMU与摄像头同理独立运行；通信的TCP桥与串口节点也独立运行。
接口包位于依赖底层；传感器和通信不依赖控制包，控制不依赖具体硬件驱动；bringup只依赖包入口。

## 原包迁移

| 原包 | 当前包/目录 | 保留入口 |
|---|---|---|
| uw_robot_control | uw_robot_control / closed_loop | control_node |
| uw_robot_allocation | uw_robot_control / allocation | allocation_node |
| uw_robot_imu | uw_robot_sensors / imu | imu_node |
| uw_robot_camera | uw_robot_sensors / camera | camera_node |
| uw_robot_teleop | uw_robot_communication / tcp | tcp_bridge_node |
| uw_robot_hardware | uw_robot_communication / stm32 | hardware_node |

原`ros2 run`中的包名需要更新；可执行文件名称不变。统一`ros2 launch uw_robot_bringup robot.launch.py`不变。
不保留空壳兼容包，避免src又出现一堆没有实现的目录。源码迁移表保存在 `migration/source_mapping.json`。

## 数据边界

| 话题 | 发布者 → 订阅者 | 内容 |
|---|---|---|
| control/cmd | TCP → 闭环 | 机体系六轴速度 u/v/w/p/q/r、四个离散命令、序号、时间 |
| imu/data | IMU → 闭环/TCP | sensor_msgs/Imu |
| depth/state | STM32通信 → 闭环/TCP | 深度、速度、有效性、数据年龄 |
| control/wrench | 闭环 → 分配 | 六维目标力/矩、解锁状态、模式、会话 |
| actuators/command | 分配 → STM32通信 | 四推进器推力、两舵角、夹爪 |
| robot/status | 闭环 → TCP/调试 | 控制状态 |
| allocation/status | 分配 → 调试 | 分配状态、可达性及误差等 |
| hardware/tx、hardware/rx | STM32通信 → 调试 | 串口文本 |
| camera/left/image_raw、camera/right/image_raw | 相机 → 视觉 | 同帧时间戳的BGR8左右图像 |

`control/cmd` 只承载物理量，不含摇杆轴：轴映射、死区、滤波和量程换算在发送端完成。
控制节点仍负责解锁/急停/指令超时仲裁和六维目标限速，发送端给出的值只是建议。
STM32深度数据经过串口进入通信包是有意设计：由串口节点独占串口并解码；传感器包不再重复打开同一设备。
图像不进入控制节点；以后识别/测距作为独立节点订阅左右图，计算结果再经明确接口接入控制。

## 修改入口

- 六轴速度到力/力矩的静态增益：`uw_robot_control/src/closed_loop/controller.cpp` 与 robot.yaml 的 damping/rate_ff。
- PID、姿态死区、定深、输出限幅：`uw_robot_control/src/closed_loop/controller.cpp`。
- 几何、分配权重、舵角求解：`uw_robot_control/src/allocation/allocator.cpp`。
- 规划有效期、门控、舵角和推力限速：`uw_robot_control/src/allocation/allocation_controller.cpp`。
- 相机采集/缓存/JPEG：`uw_robot_sensors/uw_robot_sensors/camera/capture.py`。
- UI视频服务：同目录 `stream.py`。
- IMU SDK与零点：`uw_robot_sensors/uw_robot_sensors/imu/driver.py`。
- CMD帧字段与校验：`uw_robot_communication/src/tcp/protocol.cpp`。
- STM32协议、物理编号与推力归一化：`uw_robot_communication/src/stm32/`。
- 参数数值：`uw_robot_bringup/config/robot.yaml`。
- 手柄轴映射与手柄整形：工程外的发送端（Windows UI）。
