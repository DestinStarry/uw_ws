# 当前 low_control2 与 low_control3 对比及重构

> 摄像头更新：第七路现为±90°摄像头目标，初始0°；OFF/超时保持角度，夹爪语义已废止。见[摄像头控制](摄像头舵机控制.md)。旧对比描述的是本次摄像头更新前的基准。

## 结论与证据

基准为2026-11-26用户实测成功、诊断已精简的low_control2。用户日志确认：SCR五组测试全部通过、四路UART配置检查通过、CRC正确且非全零，转动时CH1读到2300～2314 RPM。本次未更改low2。

旧low3指修改前备份中的源码，并非此前所有中间版本。它已无SYNC/MCU心跳控制门槛，但仍缺少本次low2成功的SPI时序和初始化修复。不能只凭源码认定过去所有停转、舵机运动或RPM缺失都来自同一原因；Orin的控制分配与硬件初始化仍是不同链路。

## 重构边界

CH9434硬件读写/启动配置以low2为来源；CRC解码保留在core/RpmDecoder；串口控制仍由core/ControlProtocol和CommUART1处理；PWM由Motor/Servo/MotionController处理；VoltageMonitor独立采样；TelemetryService独立非阻塞发送。转速和电压有效性不参与控制放行。

HAL失败只中止当前SPI轮询，下一轮可重试有限I/O；若最近SCR失败，需要后续SCR重新成功才恢复有效反馈。初始化三次均失败后，不在运行中插入50ms时钟切换等待；需要STM32重新上电/复位重试初始化。此时CTRL/PWM仍可工作。

保持的SPI成功路径函数可逐项与low2核对：spi_delay、reg_read、reg_write、clk_init、uart_config、uart_fifo、writeback_test、configure_and_verify。额外增加的I/O快速失败只改变故障分支。每10ms调度可能因FIFO收数延长，不能把它说成精确100Hz反馈；电调实际反馈速率由电调决定。

两帧CRC确认后有效；500ms超时使用STM32读帧时间，电调帧没有独立传感器时间戳，不能据此精确估计FIFO数据年龄。错误窗口计数BAD不等同low2固定切帧的坏帧数量。

## 手动测试兼容

数字命令是原low2行为，不是自动解锁协议。先停止ROS串口节点，只使用一个CuteCom连接，先发OFF再按单通道短时测试。未进入CTRL会话时，单次数字PWM会保持输出，最后必须OFF。若先前CTRL仍激活，数字命令不会刷新其200ms计时，仍可能被原CTRL超时清零。不要将这种保持方式误认为有200ms手动指令保护。
