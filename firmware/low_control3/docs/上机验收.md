# low_control3 上机验收

未连接实物烧录，本工程完成的是编译和离线逻辑验证。按以下顺序验收，不跳到四路带动力运行。

1. 保存当前可工作的 low_control2 固件和烧录配置，断开推进器动力，仅给控制板供电。使用原有 ST-Link/CubeProgrammer 流程烧录 `build/Release/low_control3.hex`，不要全片擦除不相关区域/改选项字节。没有在此提供自动烧录脚本。
2. 示波器/逻辑分析仪确认四路电机 PWM 上电即为 1500µs，三路舵机也为中位，频率约 50Hz。开机无旧 2000µs 脉冲；确认系统持续运行而不是看门狗反复重启。
3. 先停止占用 UART6 的 CuteCom/旧节点，只允许一个发送端。115200/8N1 下观察独立 10Hz 电压/转速上报；没有接电调反馈时 CHn 应为 --。电压与万用表对照，四路转速待有效数据时与通道一致。
4. 当前 Orin `hardware_node` 继续使用 /dev/ttyTHS2；IMU、深度计、相机在 Orin 采集。深度计已验证 I2C-7/0x76/30ba，不回接旧解算板，不依赖 MCU 深度上报。
5. 在动力断开时，先发送小幅非零 CTRL，确认上电等待回中，不直接输出；再连续发送零推力 CTRL，然后再小幅非零。检查电机方向反相与转向舵机对应关系。
6. 检查 OFF、停止发送超过 200ms、断线、乱码、超长帧及接收溢出均回中。用波形测量停机时间；SysTick 阈值约 200ms，50Hz PWM 的实际脉冲改变还可能多一个周期。停止后非零命令不能直接恢复，需零推力帧。
7. 在无动力台架检查主循环卡住时 SysTick 中位保护，以及 IRQ 不运行时 IWDG 复位；复位期间输出与电调失信号行为需实测。不要在实物带动力时用断点测试卡死。
8. 逐路接电调/推进器，按厂家允许的水中或台架条件进行低幅测试。准备直接切断动力的开关，确认通道及正反方向。极对数默认为原值 7，必须核实；CRC 帧重同步与断开反馈后的 -- 也要测。
9. 四路方向、急停、断链、重启与反馈行为均正确后，才进入手动运动、姿态闭环、定深测试。先验证下潜深度增大及控制纠偏方向；固件编译成功不是闭环可直接下水的证明。

## 建议的 Orin 观察命令

```bash
source ~/uw_ws/install/setup.bash
ros2 topic echo /hardware/tx
ros2 topic echo /hardware/rx
```

`dry_run:=true` 不打开 STM32 串口，只适合看拟发送命令；实际 UART 联调需显式 `dry_run:=false`。不要同时运行整组与第二个 hardware_node。

## 兼容边界

- 新 MCU 默认取消旧数字 PWM 调试命令；用正常 CTRL/OFF 流程逐路测试。
- 新 MCU 加入零推力恢复要求；Orin/UI 尚没有独立显示它，需要从原始 rx 看 NEUTRAL_REQUIRED。
- 新 MCU 不上报深度、板温或板载 IMU；CPU 温度来自 Orin 新监测节点。
- 原 Orin 转速订阅代码无需改字段即可使用；MCU 诊断旗标暂只在原始 rx 中可见。
- 下行文本目前没有 CRC/序号，仍可能接受被干扰后恰好合法的数值。要加下一代协议需 MCU/Orin 双端同时升级。
