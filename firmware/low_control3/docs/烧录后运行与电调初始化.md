# 烧录后运行与电调重新初始化

STM32程序保存在Flash中，正常断电重启不会丢失，不需要每次开机重新烧录。只有更新固件才需要烧录。

## VS Code两种方式

原F5调试配置保留`runToEntryPoint: main`，会运行到main入口后暂停；此时HAL/时钟/PWM初始化尚未执行，需要按F5继续。不要用按板上RST代替调试器继续运行。

日常更新请选择菜单“终端 → 运行任务 → Flash and Run low_control3 Debug”。先Shift+F5结束旧调试会话，避免两个OpenOCD实例争用CMSIS-DAP。新任务依赖现有Debug构建任务，随后调用OpenOCD：

```text
program {固件ELF路径} verify reset exit
```

这会烧录、校验、复位运行，然后退出OpenOCD，不设置main临时断点。任务已配置，本次没有实际执行烧录。现有F5调试设置、CMSIS-DAP接口、PWM及电调参数均未改。

## 建议操作顺序

1. 先锁定推进器，停止Orin整机ROS进程，结束VS Code调试会话。
2. 运行上述Flash and Run任务，等待报告校验成功且烧录进程正常退出；不要立即按板上RST。
3. 观察STM32串口遥测和RDBG初始化状态，确认程序在运行、INIT READY/CFG F。
4. 等电调完成中位初始化，再启动Orin和电脑UI，最后解锁测试。

烧录或断点暂停会打断原PWM；若电调当时仍供电，其状态不会因只复位STM32而必然重新初始化。若规范烧录后仍不能转，需要分别记录：STM32有无遥测、是否持续收到CTRL、是否输出1500us/目标PWM，以及电调只断电重上电能否恢复，才能区分软件启动与电调状态。不能仅凭整机重启恢复就认定是固件错误或电调损坏。

low3已在开PWM前写中位1500us，因此这次不再改动推进器控制代码。新任务解决调试暂停与烧录后运行方式，不代表已经实物验证电调恢复。
