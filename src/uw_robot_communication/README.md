# 通信包

两个节点只负责协议和设备收发，不计算姿态控制或推力分配。

| 文件 | 作用 |
| --- | --- |
| `src/tcp/protocol.cpp` | 严格解析 CMD 文本，验证六轴物理量和四个按钮 |
| `src/tcp/tcp_bridge_node.cpp` | 单客户端非阻塞 TCP，换行拆帧、指令发布、遥测回传、断线急停 |
| `src/stm32/protocol.cpp` | 内部执行器指令转 CTRL 文本，混合遥测提取深度 |
| `src/stm32/hardware_node.cpp` | 串口配置、周期收发、半帧续写、命令看门狗、深度状态发布 |

## 数据路径

`TCP CMD -> control/cmd -> 控制/分配 -> actuators/command -> STM32 CTRL`。
STM32 原始行发布到 `hardware/rx`，待发送文本发布到 `hardware/tx`。
`depth/state` 来自解析出的深度；目前没有把所有原始遥测字段转换为专用 ROS 消息。

## 帧格式

`CMD:u,v,w,p,q,r,arm,estop,depth,loop\n`，共 10 个字段。
前 6 个是机体系线速度 m/s 与角速度 rad/s，后 4 个是 0/1 离散命令。
越界、非有限值或字段数不符时整帧丢弃，不截断；`OFF` 单独作为急停行。

## 关键约定

- TCP 每 5 ms 最多读 4 批，串口每 20 ms 最多读 8 批；均不阻塞等待完整一行。
- TCP 缓存处理半包/粘包；发送缓存处理部分写出。断线和 OFF 都发布急停请求。
- 串口半帧发送完成后才切换命令；命令超时发 OFF，持续写阻塞超过 100 ms 报错退出。
- 内部推力顺序 `[1上,3下,2右,4左]`，串口 CTRL 按物理顺序 `[1,2,3,4]` 编码。
- 推力正/反向分别按 33 N / 24.5 N 归一化，角度按 pi/2 归一化。
- `dry_run=true` 不打开串口，仍发布调试话题及深度有效性状态。
- 入口检查 ROS 时间戳；本地持续超时使用单调时钟。

从 `tick()` 读执行顺序，再看收发辅助函数；纯文本规则在 `protocol.cpp`，可脱离 ROS 测试。

## 当前直接串口模式

actuators/command按50Hz转换为CTRL/OFF，无SYNC握手和MCU心跳门槛；转速缺失不参与控制。保留上游命令超时、数值/时间戳校验和串口写阻塞退出。原始接收/TCP订阅队列为100以接收多行遥测。详见[简化通信与测试](../../docs/简化通信与测试.md)。
